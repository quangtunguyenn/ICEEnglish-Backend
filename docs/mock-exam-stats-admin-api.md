# Mock exam statistics for Admin/Staff

All endpoints are restricted to `ADMIN` and `TEACHER` authorities (the staff roles used by this backend). A missing or invalid token receives `401`; an authenticated user without one of those roles receives `403`. Successful responses use the backend's current direct JSON response format and camelCase property names.

All business timestamps are generated by the backend server and use `Asia/Ho_Chi_Minh` (`+07:00`); the frontend must not use the student's device clock to decide start, expiry, or submission times.

Statistics include submitted MOCK submissions only (`submittedAt` is set); unfinished attempts are excluded. Scores are computed as `totalCorrect / totalQuestions * 10` and rounded to two decimal places. If a student has multiple submitted attempts for the same exam, only the attempt with the highest score is counted. Ties use earlier `submittedAt`, shorter duration, then ascending submission ID. This is applied consistently to exam-list summaries, overview, question statistics, and the leaderboard.

The existing schema has no `published_at` or email column. `publishedAt` in the exam list therefore reflects the exam's `createdAt`; leaderboard items omit `email` rather than misrepresenting `username` as an email. No schema or migration changes are required.

## Published MOCK exam list

`GET /api/v1/admin/mock-exams?page=0&size=20&keyword=`

Filters to published MOCK exams, searches title case-insensitively, and sorts by `createdAt` descending (ID ascending as a stable tie-breaker). Page size must be from 1 to 100. `averageScore` is `null` when no student has submitted.

Response: `{ "items": [...], "page": 0, "size": 20, "totalElements": 5, "totalPages": 1 }`.

## Overview

`GET /api/v1/admin/mock-exams/{examId}/stats/overview`

Returns score average, extrema, median, average elapsed seconds, and all score ranges, including empty ranges. Score ranges are half-open `[min,max)` and the exact score `10` has its own `min=10,max=10` bucket. Default boundaries are `0,3,4,5,6,7,8,9,10`; custom boundaries can be provided with `?buckets=0,3,4,5,6,7,8,9,10`. Boundaries must be strictly increasing from 0 to 10. Bucket percentages use the selected submitted attempts as denominator; with no submissions, every bucket has count and percent `0`.

When there are no submitted attempts, `submittedCount` is `0`, score and duration metrics are `null`, and the distribution is still returned.

## Question statistics

`GET /api/v1/admin/mock-exams/{examId}/stats/questions`

Questions are returned in original part/question order. `questionNumber` is assigned 1..N in that order. `answeredCount` counts non-empty selections; `unansweredCount` includes submitted attempts with no selection. `correctPercent` and `wrongPercent` are calculated over answered attempts only; option counts always include A, B, C, and D, and their percentages use the same answered denominator. Those percentages are `null` when nobody answered that question.

## Leaderboard

`GET /api/v1/admin/mock-exams/{examId}/stats/top?limit=10`

`limit` defaults to 10 and must be from 1 to 100. Ordering is score descending, submitted time ascending, elapsed duration ascending, then submission ID ascending. Ranks are consecutive. The response omits `email` because the current user schema has no email field.

For overview, question statistics, and leaderboard, a missing exam or an exam that is not MOCK returns `404`.
